# Final submission checklist

## Prepared

- Public repository: https://github.com/sankalp2515/TraceVerdict
- Working source, reproducible examples, CI and exact sponsor receipts.
- Genuine nonfixture capture → governed evidence → investigation → repair → replay path.
- Measured NVIDIA model comparison, including failures and evaluation limitations.
- Pitch deck, submission text and local JSON draft in `submission/`.
- Independent Docker API, web, local proxy and source services; separate Zetaris stack and native Nightshift runtime.
- Pre-existing foundation declaration: `docs/NEW_WORK.md`.

## Required final actions

1. Confirm registration/profile and final team details on the portal. No saved submission has been verified.
2. Resolve Track 2 eligibility for extending prior work with the organizer; the FAQ explicitly describes extensions under Wildcard. Keep the foundation disclosure. Team ownership does not establish track eligibility.
3. Record and upload the required 1–4 minute video, with a real Nightshift request and keys hidden. Use `submission/DEMO_SCRIPT.md`.
4. Put the accessible video URL and final deck URL into `submission/submission-draft.json` and the portal. Review every submission field and submit before the official deadline. A local draft or GitHub push is not a portal submission.
5. Verify the portal's submitted status and access to all final links while signed out.

## Highest-value evidence for judging

- Show one complete case, not a tour of disconnected modules.
- Show the rejected restrictive control beside the passing targeted repair: 6/8 versus 8/8 legitimate model-driven tasks, and 18/20 versus 20/20 fixed-action tasks in the retained comparison.
- Show an actual critic disagreement or correction, source evidence and uncertainty.
- Explain why Lightning handles investigation and Ultra handles replay; link the 48 retained development trials. Do not describe model resistance as proof of policy enforcement.
- Import an original capture through the reviewer flow, publish it to the three sources and read it back through Zetaris. Explain that capture authenticity is operator-attested.
- Show hash-bound human review and export; do not imply automatic deployment.

## Product readiness limits

Browser automation is disabled in Work settings, so the new intake controls still need a fresh browser walkthrough. API and component tests plus the actual nonfixture live run cover the underlying path. Public hosting is not listed as mandatory in the reviewed official submission requirements; any cloud is permitted. If a hosted trial is chosen, HTTPS, protected sponsor networking and deployment checks remain necessary.

Broader third-party tool executors, self-service accounts/credentials, SSO, operational monitoring, retention policy, capacity/SLO measurements and whole-platform disaster recovery remain product work. The current replay tools are a local outbox and deterministic artifact reader. Winning is subject to eligibility and judges' decisions, not a guaranteed outcome.
